# PostgreSQL pgvector và Machine Learning

## Tổng quan

pgvector là một extension cho PostgreSQL cho phép lưu trữ và tìm kiếm vector embeddings trực tiếp trong database. Với sự phát triển mạnh mẽ của generative AI và large language models (LLMs), việc store và query vectors đã trở thành một requirement phổ biến trong các modern applications.

pgvector cung cấp:

- Vector data type cho việc lưu trữ high-dimensional vectors
- Distance operators để tính toán similarity
- Index structures (HNSW, IVFFlat) cho approximate nearest neighbor (ANN) search
- Tích hợp hoàn toàn với PostgreSQL ecosystem

Trong enterprise contexts, pgvector cho phép xây dựng các ứng dụng như semantic search, recommendation systems, anomaly detection, và RAG (Retrieval-Augmented Generation) mà không cần separate vector database.

Tài liệu này nhằm mục đích:

## Các khái niệm chính

### Vector Embeddings là gì?

Vector embeddings là numerical representations của data (text, images, audio) trong một high-dimensional vector space. Similar items có vectors gần nhau trong không gian này.

```
Example: 3-dimensional embeddings visualization

                [book]
                 /\
                /  \
     [doc] ----/    \---- [article]
                \  /
                 \/
           [paper]
```

**Common embedding dimensions**:

- OpenAI text-embedding-3-small: 1536 dimensions
- OpenAI text-embedding-3-large: 3072 dimensions
- Sentence-transformers (all-MiniLM-L6-v2): 384 dimensions
- CLIP image embeddings: 512 dimensions

### Distance Operators

pgvector cung cấp các distance operators:

```sql
-- 1. L2 Distance (Euclidean) - default
-- Giảm thiểu khoảng cách Euclidean
-- Tốt cho: general similarity, clustering
SELECT embedding <=> '[0.1, 0.2, 0.3]'::vector AS l2_distance
FROM documents;

-- 2. Negative Inner Product (IP)
-- Tối đa hóa inner product
-- Tốt cho: normalized vectors, recommendation
SELECT embedding <#> '[0.1, 0.2, 0.3]'::vector AS ip_distance
FROM documents;

-- 3. Cosine Distance
-- Đo góc giữa hai vectors
-- Tốt cho: text similarity, когда важна только ориентация
SELECT embedding <=> '[0.1, 0.2, 0.3]'::vector AS cosine_distance
FROM documents;

-- Tính cosine similarity từ cosine distance
SELECT 1 - (embedding <=> '[0.1, 0.2, 0.3]'::vector) AS cosine_similarity
FROM documents;
```

```sql
-- Similarity search examples
-- Find 5 most similar documents
SELECT id, content,
       1 - (embedding <=> $1::vector) AS similarity
FROM documents
ORDER BY embedding <=> $1::vector
LIMIT 5;

-- Find documents với similarity > 0.8
SELECT id, content
FROM documents
WHERE 1 - (embedding <=> $1::vector) > 0.8
ORDER BY embedding <=> $1::vector;
```

### Vector Indexing

Vector indexes là critical cho performance khi làm việc với large datasets.

**Không có index (brute force)**:

```sql
-- Sequential scan - O(n) time
-- Good for < 10,000 vectors
SELECT * FROM documents
ORDER BY embedding <=> $1::vector
LIMIT 5;
```

### HNSW Index (Hierarchical Navigable Small World)

HNSW là thuật toán ANN (Approximate Nearest Neighbor) hiệu đại, cung cấp:

- Excellent query performance
- High recall rate
- Build time tương đối cao
- Memory consumption cao

```sql
-- Create HNSW index
CREATE INDEX ON documents USING hnsw (embedding vector_l2_ops);

-- Hoặc chỉ định parameters
CREATE INDEX ON documents USING hnsw (embedding vector_l2_ops)
WITH (m = 16, ef_construction = 64);

-- Parameters:
-- m: Số connections per layer (default: 16, range: 2-100)
--   - Higher = better recall, more memory, slower build
-- ef_construction: Size of dynamic list (default: 64, range: 4-1000)
--   - Higher = better recall, slower build

-- Query với HNSW index
-- ef_search: Query-time search width (default: 40)
SET hnsw.ef_search = 100;  -- Higher = better recall

SELECT * FROM documents
ORDER BY embedding <=> $1::vector
LIMIT 5;
```

### IVFFlat Index (Inverted File Flat)

IVFFlat là clustering-based index:

- Faster build time
- Lower memory usage
- Good recall với right parameters
- Performance phụ thuộc vào data distribution

```sql
-- Create IVFFlat index
CREATE INDEX ON documents USING ivfflat (embedding vector_l2_ops);

-- Với custom parameters
CREATE INDEX ON documents USING ivfflat (embedding vector_l2_ops)
WITH (lists = 100);

-- Parameters:
-- lists: Số clusters (default: 100)
--   - Guidelines: 
--     - < 1M rows: 100 * (rows / 1M)
--     - > 1M rows: sqrt(rows)
--     - Range: 1-10000

-- Probes: Số clusters để search (default: 1)
SET ivfflat.probes = 10;

SELECT * FROM documents
ORDER BY embedding <=> $1::vector
LIMIT 5;
```

### Chọn Index Type

| Criteria | HNSW | IVFFlat |
|----------|------|---------|
| Build time | Slower | Faster |
| Query speed | Faster | Moderate |
| Memory usage | Higher | Lower |
| Recall | Higher | Lower (need more probes) |
| Data distribution sensitivity | Low | High |
| Best for | Production, high accuracy | Large datasets, fast build |

**Recommendations**:

```sql
-- HNSW: Khi cần high recall và performance
-- - Production systems
-- - < 10M vectors
-- - Fast queries critical

-- IVFFlat: Khi cần fast build và lower memory
-- - Large datasets (> 10M vectors)
-- - Frequent bulk loading
-- - Development/Testing

-- No index: Khi data nhỏ và cần exact results
-- - < 10,000 vectors
-- - Development/Testing
```

```python
# Python: Efficient bulk insert
import pandas as pd
import numpy as np
from openai import OpenAI
from psycopg2.extras import execute_values

client = OpenAI()

def generate_and_store_embeddings(documents, batch_size=100):
    conn = psycopg2.connect("postgresql://localhost:5432/mydb")
    cur = conn.cursor()
    
    embeddings_data = []
    
    for i in range(0, len(documents), batch_size):
        batch = documents[i:i + batch_size]
        response = client.embeddings.create(
            input=batch,
            model="text-embedding-3-small"
        )
        
        for doc, emb_response in zip(batch, response.data):
            embeddings_data.append({
                'content': doc,
                'embedding': emb_response.embedding
            })
        
        # Batch insert
        execute_values(
            cur,
            "INSERT INTO documents (content, embedding) VALUES %s",
            [(d['content'], d['embedding']) for d in embeddings_data]
        )
        conn.commit()
        embeddings_data = []
        
        print(f"Processed {i + len(batch)}/{len(documents)} documents")
    
    cur.close()
    conn.close()
```

## Common Patterns

### Pattern 1: Semantic Search

```sql
-- Semantic search function
CREATE OR REPLACE FUNCTION semantic_search(
    query_text TEXT,
    match_count INT DEFAULT 5,
    similarity_threshold FLOAT DEFAULT 0.7
)
RETURNS TABLE (
    id BIGINT,
    content TEXT,
    similarity FLOAT
) AS $$
DECLARE
    query_embedding vector;
BEGIN
    -- Query embedding cần được generate (giả định stored trong temp)
    -- Trong thực tế, gọi embedding API ở application layer
    
    RETURN QUERY
    SELECT 
        d.id,
        d.content,
        1 - (d.embedding <=> query_embedding) AS similarity
    FROM documents d
    WHERE 1 - (d.embedding <=> query_embedding) > similarity_threshold
    ORDER BY d.embedding <=> query_embedding
    LIMIT match_count;
END;
$$ LANGUAGE plpgsql STABLE;
```

```python
# Python semantic search
def semantic_search(query_text, top_k=5):
    # Generate query embedding
    query_embedding = generate_embedding(query_text)
    
    # Search in database
    cur.execute("""
        SELECT id, content, 
               1 - (embedding <=> %s) AS similarity
        FROM documents
        ORDER BY embedding <=> %s
        LIMIT %s
    """, (query_embedding, query_embedding, top_k))
    
    return cur.fetchall()
```

### Pattern 2: Hybrid Search (Vector + Keyword)

```sql
-- Hybrid search với weighted scoring
CREATE OR REPLACE FUNCTION hybrid_search(
    query_text TEXT,
    query_embedding vector,
    match_count INT DEFAULT 10
)
RETURNS TABLE (
    id BIGINT,
    content TEXT,
    combined_score FLOAT
) AS $$
BEGIN
    RETURN QUERY
    WITH ranked AS (
        SELECT 
            d.id,
            d.content,
            d.embedding,
            ts_rank(to_tsvector('english', d.content), 
                    plainto_tsquery('english', query_text)) AS keyword_rank,
            1 - (d.embedding <=> query_embedding) AS vector_similarity
        FROM documents d
        WHERE 
            to_tsvector('english', d.content) @@ 
            plainto_tsquery('english', query_text)
            OR 1 - (d.embedding <=> query_embedding) > 0.5
    )
    SELECT 
        r.id,
        r.content,
        (r.keyword_rank * 0.3 + r.vector_similarity * 0.7)::FLOAT AS combined_score
    FROM ranked r
    ORDER BY combined_score DESC
    LIMIT match_count;
END;
$$ LANGUAGE plpgsql STABLE;
```

```python
# Python hybrid search với reranking
from sentence_transformers import CrossEncoder

def hybrid_search_with_rerank(query, documents, top_k=10, rerank_top=5):
    # Initial vector search
    results = semantic_search(query, top_k=top_k * 2)
    
    # Rerank với CrossEncoder
    pairs = [(query, doc['content']) for doc in results]
    cross_encoder = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
    scores = cross_encoder.predict(pairs)
    
    # Combine và return top results
    for doc, score in zip(results, scores):
        doc['cross_score'] = float(score)
    
    results.sort(key=lambda x: x['cross_score'], reverse=True)
    return results[:rerank_top]
```

### Pattern 3: Recommendation System

```sql
-- User-based recommendation
CREATE OR REPLACE FUNCTION recommend_for_user(
    user_id BIGINT,
    recommend_count INT DEFAULT 10
)
RETURNS TABLE (
    item_id BIGINT,
    score FLOAT
) AS $$
DECLARE
    user_embedding vector;
BEGIN
    -- Get user's preference embedding (average of interacted items)
    SELECT AVG(embedding) INTO user_embedding
    FROM user_interactions
    WHERE user_id = user_id;
    
    RETURN QUERY
    SELECT 
        i.item_id,
        1 - (i.embedding <=> user_embedding) AS score
    FROM items i
    WHERE i.item_id NOT IN (
        SELECT item_id FROM user_interactions WHERE user_id = user_id
    )
    ORDER BY i.embedding <=> user_embedding
    LIMIT recommend_count;
END;
$$ LANGUAGE plpgsql STABLE;
```

### Pattern 4: RAG (Retrieval-Augmented Generation)

```sql
-- RAG context retrieval
CREATE OR REPLACE FUNCTION rag_retrieve(
    query_embedding vector,
    context_window INT DEFAULT 3,
    similarity_threshold FLOAT DEFAULT 0.75
)
RETURNS TABLE (
    chunk_id BIGINT,
    chunk_text TEXT,
    source_doc TEXT,
    similarity FLOAT
) AS $$
BEGIN
    RETURN QUERY
    WITH ranked_chunks AS (
        SELECT 
            c.id AS chunk_id,
            c.text AS chunk_text,
            d.title AS source_doc,
            1 - (c.embedding <=> query_embedding) AS similarity,
            ROW_NUMBER() OVER (
                PARTITION BY d.id 
                ORDER BY c.embedding <=> query_embedding
            ) AS doc_rank
        FROM chunks c
        JOIN documents d ON c.document_id = d.id
        WHERE 1 - (c.embedding <=> query_embedding) > similarity_threshold
    )
    SELECT 
        rc.chunk_id,
        rc.chunk_text,
        rc.source_doc,
        rc.similarity
    FROM ranked_chunks rc
    WHERE rc.doc_rank <= context_window
    ORDER BY rc.similarity DESC;
END;
$$ LANGUAGE plpgsql STABLE;
```

```python
# Python RAG implementation
def rag_query(user_query, model="gpt-4", max_tokens=1000):
    # 1. Generate query embedding
    query_embedding = generate_embedding(user_query)
    
    # 2. Retrieve relevant context
    context_results = execute_rag_retrieve(query_embedding, top_k=5)
    context = "\n\n".join([
        f"[Source: {r['source_doc']}]\n{r['chunk_text']}"
        for r in context_results
    ])
    
    # 3. Build prompt
    prompt = f"""Based on the following context, answer the user's question.

Context:
{context}

Question: {user_query}

Answer:"""
    
    # 4. Generate response
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        max_tokens=max_tokens
    )
    
    return {
        'answer': response.choices[0].message.content,
        'sources': context_results
    }
```

### Pattern 5: Clustering và Anomaly Detection

```sql
-- Simple clustering using vector quantization
CREATE OR REPLACE FUNCTION cluster_vectors(
    table_name TEXT,
    embedding_column TEXT,
    num_clusters INT DEFAULT 100
)
RETURNS TABLE (
    cluster_id INT,
    cluster_center vector,
    count BIGINT
) AS $$
BEGIN
    RETURN QUERY
    WITH centroids AS (
        SELECT 
            row_number() OVER (ORDER BY random()) AS cluster_id,
            (AVG(embedding))[0:num_clusters] AS center  -- Simplified
        FROM documents
        GROUP BY (random() * num_clusters)::INT
    )
    SELECT 
        c.cluster_id,
        c.center,
        COUNT(*) AS count
    FROM centroids c
    GROUP BY c.cluster_id, c.center
    ORDER BY count DESC;
END;
$$ LANGUAGE plpgsql;
```

## Troubleshooting

### Vấn đề 1: Slow HNSW Index Build

**Triệu chứng**: CREATE INDEX mất quá nhiều thời gian.

**Giải pháp**:

```sql
-- 1. Giảm m và ef_construction (trade-off recall)
CREATE INDEX ON documents USING hnsw (embedding vector_l2_ops)

-- 2. Tăng maintenance_work_mem
SET maintenance_work_mem = '2GB';

-- 3. Bulk load trước, sau đó build index
-- 4. Sử dụng IVFFlat cho large datasets nếu acceptable
```

### Vấn đề 2: Low Recall với IVFFlat

**Giải pháp**:

```sql
-- 1. Tăng số lists
-- Guidelines: lists = sqrt(total_rows)
CREATE INDEX ON documents USING ivfflat (embedding vector_l2_ops)
WITH (lists = 1000);

-- 2. Tăng probes khi query
SET ivfflat.probes = 50;

```

```sql
-- Step 4: Create update trigger
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER documents_updated_at
    BEFORE UPDATE ON documents
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

-- Step 5: Create search function
CREATE OR REPLACE FUNCTION search_documents(
    query_embedding vector,
    search_query TEXT DEFAULT NULL,
    category_filter VARCHAR(50) DEFAULT NULL,
    limit_count INT DEFAULT 10
)
RETURNS TABLE (
    id BIGINT,
    title TEXT,
    content TEXT,
    author VARCHAR,
    category VARCHAR,
    rank FLOAT,
    similarity FLOAT
) AS $$
BEGIN
    RETURN QUERY
    WITH vector_results AS (
        SELECT 
            d.id,
            d.title,
            d.content,
            d.author,
            d.category,
            ts_rank(
                to_tsvector('english', d.title || ' ' || content),
                plainto_tsquery('english', COALESCE(search_query, ''))
            ) AS rank,
            1 - (d.embedding <=> query_embedding) AS similarity
        FROM documents d
        WHERE 
            (category_filter IS NULL OR d.category = category_filter)
            AND (
                search_query IS NULL 
                OR to_tsvector('english', d.title || ' ' || d.content) 
                    @@ plainto_tsquery('english', search_query)
            )
    )
    SELECT 
        vr.*,
        (vr.rank * 0.2 + vr.similarity * 0.8)::FLOAT AS final_score
    FROM vector_results vr
    ORDER BY final_score DESC
    LIMIT limit_count;
END;
$$ LANGUAGE plpgsql STABLE;
```

```sql
    tablename,
    indexname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch,
    pg_size_pretty(pg_relation_size(indexrelid)) AS index_size
FROM pg_stat_user_indexes ui
JOIN pg_index i ON ui.indexrelid = i.indexrelid
WHERE indexname LIKE '%embedding%' 
   OR indexname LIKE '%vector%';

-- Check index usage
SELECT * FROM vector_index_stats ORDER BY index_size DESC;

-- Check for bloat
SELECT 
    schemaname,
    tablename,
    indexname,
    pg_size_pretty(pg_relation_size(indexrelid)) AS size,
    idx_scan
FROM pg_stat_user_indexes
WHERE indexname LIKE '%vector%'
AND idx_scan = 0;
```
