# Simple English Writer

Transform complex technical content into clear, accessible Simple English.

## Philosophy

Write for your audience, not for yourself. Simple English is not "dumbed down" - it's clarity that respects the reader's time and intelligence.

## Core Principles

### 1. Use Common Words
- Prefer everyday vocabulary over jargon
- Replace complex words with simpler alternatives
- Use the shortest word that carries the same meaning

### 2. Short Sentences
- One idea per sentence
- Average sentence length: 15-20 words
- Maximum sentence length: 25 words
- Break long sentences into two

### 3. Active Voice
- Subject + Verb + Object
- "The system saves the file" not "The file is saved by the system"
- Active voice is clearer and shorter

### 4. Concrete Language
- Use specific examples
- Avoid abstract concepts when concrete ones work
- Show, don't tell

## Sentence Transformations

### Before (Complex)
> "The implementation of this functionality will facilitate the optimization of workflow processes."

### After (Simple)
> "This tool helps you work faster."

### Before (Complex)
> "Users are required to utilize the authentication mechanism prior to accessing the system."

### After (Simple)
> "You must log in before using the system."

### Before (Complex)
> "The configuration file contains numerous parameters which subsequently affect the behavior of the application."

### After (Simple)
> "The settings file controls how the app works."

## Structure Guidelines

### Paragraphs
- One main idea per paragraph
- 2-4 sentences per paragraph
- Lead with the most important information
- Use transition words sparingly: "also", "but", "then"

### Lists
- Use bullet points for 3-5 items
- Keep items parallel in structure
- Each item one line if possible

### Headings
- Descriptive, not clever
- Plain language
- Tell the reader what to expect

## Technical Content Simplification

### For Documentation
1. Identify the audience
2. Find the main action
3. Remove unnecessary details
4. Use numbered steps for processes
5. Add examples

### For APIs
1. Explain what it does first
2. Show a simple example
3. List only essential parameters
4. State expected output clearly

### For Error Messages
1. What went wrong (plain terms)
2. What to do about it
3. Keep under 20 words if possible

## Examples

### Error Message
**Complex:** "An authentication failure has occurred due to invalid credentials. Please verify your username and password and attempt authentication again."

**Simple:** "Wrong username or password. Check your login and try again."

### API Documentation
**Complex:** "The `createUser` function facilitates the creation of user accounts within the system by accepting a JSON payload containing user attributes and returning a user object upon successful completion."

**Simple:** "Use `createUser` to make a new account. Send user details, get back the new user."

## Voice and Tone

### Do
- Be friendly but professional
- Use "you" and "we"
- Address the reader directly
- Be specific and concrete
- Show confidence

### Don't
- Use jargon without explanation
- Write in passive voice
- Make sentences too long
- Use filler words
- Over-explain obvious things

## Quick Checklist

Before finishing, review your text:

- [ ] All sentences under 25 words?
- [ ] Mostly active voice?
- [ ] Common words used?
- [ ] One idea per sentence?
- [ ] Technical terms explained?
- [ ] Clear action steps?
- [ ] Reader knows what to do?

## Usage

### When to Use
- Writing for non-native English speakers
- Creating beginner tutorials
- Simplifying error messages
- Making documentation accessible
- Explaining complex topics

### When NOT to Use
- Academic papers (unless requested)
- Legal documents
- Technical specifications for experts
- Creative writing (unless simplifying for kids)
